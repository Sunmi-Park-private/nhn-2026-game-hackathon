## 0. 가장 먼저 알아야 할 것

**파일을 `public/assets/` 아래 정해진 경로에 드롭하면 게임에 자동 반영된다.**
개발자를 기다릴 필요가 없고, 개발 서버가 켜져 있으면 **핫리로드로 즉시 확인**된다.
코드를 건드리지 않는다.

파일이 없는 슬롯은 색 육각·창살 프레임 같은 폴백으로 그려진다.
**하나도 없어도 게임이 성립하고, 일부만 도착해도 정상 동작한다.**

## 1. 화면 규격 — 2026-09-04 변경

**전체는 16:9 가로, 게임은 중앙 9:16 세로 컬럼 안에서만 논다.**
좌우 패널은 가로 화면을 채우는 헛간 장식이다.

```
┌──────────────┬────────────┬──────────────┐
│   좌 패널    │   게임판   │   좌우 패널  │
│   175:288    │    9:16    │    175:288   │
└──────────────┴────────────┴──────────────┘
                전체 16:9
```

검산: 9/16 + 2×(175/288) = 1.77778 = 16/9. **오차 0의 정확한 분할이다.**

| 항목 | 값 |
|---|---|
| 전체 화면 | **16:9** |
| 중앙 게임판 | **9:16** ← 게임 콘텐츠는 전부 여기 |
| 좌·우 패널 | 각 **175:288** |

### 아트 제작 크기 (권장)

높이를 2304로 잡으면 세 조각이 전부 정수로 떨어진다.

| 슬롯 | 크기 |
|---|---|
| 전체 배경 (한 장으로 낼 때) | **4096 × 2304** |
| 중앙 게임판 배경 | **1296 × 2304** |
| 좌 패널 · 우 패널 | 각 **1400 × 2304** |

절반 크기(2048×1152 / 648×1152 / 700×1152)도 무방하다. 비율만 정확하면 된다.

### 좁은 화면에서

세로 폰처럼 뷰포트가 9:16보다 좁으면 **중앙 컬럼만 보이고 좌우 패널은 잘린다.**
게임은 그대로 성립하므로, **게임에 필요한 것은 하나도 좌우 패널에 두지 말 것.**
좌우 패널은 장식 전용이다.

## 2. 육각 타일 — 최우선 6종

### 규격

| 항목 | 값 |
|---|---|
| 육각형 방향 | **pointy-top** (위아래가 뾰족, 좌우가 평평한 수직 변) |
| **가로:세로 비율** | **√3 : 2 ≈ 0.866 : 1** ← 이것만 지키면 된다 |
| 제작 권장 크기 | **312 × 360px** (넉넉하게. 게임이 알아서 축소한다) |
| 형식 | PNG 알파 (WebP 자동 변환됨) |

> **화면상 크기는 신경 쓰지 않아도 된다.** 나무 프레임 안쪽 폭을 7로 나눠
> 코드가 자동으로 계산한다(현재 셀 폭 약 45px). 프레임 두께가 바뀌면 타일 크기도
> 따라 바뀌므로, **아트는 비율만 맞추고 크게 그리면 된다.**

> 타일은 서로 **맞물려 격자를 이룬다.** 육각형 외곽선이 인접 타일과 딱 붙었을 때
> 틈이나 겹침이 없어야 한다. 그림자·하이라이트는 육각 경계 **안쪽**에 둘 것.

### 6색 — 순서가 중요하다

| 순서 | 색 | 비고 |
|---:|---|---|
| 1 | 🔴 **빨강** | 가장 흔한 색. 발사체로도 판 위에서도 제일 자주 보인다 |
| 2 | 🟡 노랑 | |
| 3 | 🟢 초록 | |
| 4 | 🔵 파랑 | |
| 5 | 🟣 보라 | |
| 6 | 🟠 **황금** | 가장 귀한 색. 판에 드물게 깔린다 — 다른 5색보다 **명백히 특별해 보여야** 한다 |

**이 순서는 가시광선의 파장 순서다.** 빨강에서 보라로 갈수록 파장이 짧아진다.
6색은 서로 **등급이 아니라 대등한 색**이지만, 뒤로 갈수록 채도·광택이 조금씩 올라가는
방향으로 그리면 판이 한 줄의 스펙트럼으로 읽힌다. 황금만 금속 광택 + 발광으로 확실히 뺀다.

> **같은 색 3개가 붙으면 그대로 터진다.** 색이 다른 색으로 바뀌는 연출은 없으므로,
> 색끼리 「이어지는」 그림(예: 노랑이 초록의 애벌레처럼 보이는 디자인)은 필요 없다.

## 4. 우리(케이지)와 동물

**케이지는 타일보다 큰 육각 한 장이다.** 판 한가운데에 큰 육각 창살이 놓이고,
**1칸짜리 육각 타일 12개가 그 둘레를 감싼다.** 이 「큰 육각을 작은 육각이 두르는」 그림이
판의 얼굴이므로, 케이지는 타일을 확대한 것이 아니라 **그 자체로 완성된 한 장**으로 그린다.

| 항목 | 값 |
|---|---|
| 점유 크기 | 격자 7칸(중심 + 이웃 6) — 화면에서는 **큰 육각 한 장** |
| 육각형 방향 | **flat-top** — 위아래가 **수평**, 좌우가 뾰족하다. **타일과 반대다** |
| **가로:세로 비율** | **2 : √3 ≈ 1 : 0.866** ← 타일의 √3:2를 뒤집은 값이다 |
| 화면 크기 | 타일 가로폭의 약 **3배** |
| 제작 권장 | **900 × 780px** |
| 구성 | 육각 윤곽 + 세로 창살 + 자물쇠 |

> **방향을 헷갈리지 말 것.** 타일은 pointy-top(위아래 뾰족), 케이지는 flat-top(위아래 수평)이다.
> 30° 어긋나 있어서 창살의 뾰족한 좌우가 타일의 수직 변 사이로 파고들며 맞물린다.
> 같은 방향으로 그리면 이 맞물림이 사라지고 케이지가 그냥 「큰 타일」로 보인다.

> 타일 한 칸이 작아졌다(격자 11열 × 16행). 타일 아트는 **비율만 맞으면 크게 그려도 된다** —
> 게임이 축소한다. §2의 규격은 그대로다.

**진행도 표시.** 케이지 **위쪽** 타일에는 잠금이 풀릴 때까지 금이 한 줄씩 늘어난다(최대 5줄).
지금은 코드가 흰 선으로 그리지만, 금 간 타일 아트를 5단계로 주면 그걸 쓴다. 필수는 아니다.

**필요한 상태 2종 × 동물 6종 = 12장.** 게임이 같은 자리에서 갈아끼운다.
갇힌 동물이 누구냐에 따라 창살도 달라지므로 **동물마다 따로 그린다** —
한 종만 도착해도 그 종은 아트로, 나머지는 폴백으로 정상 동작한다.

| 슬롯 | 형식 | 언제 보이나 |
|---|---|---|
| 창살(잠금) | **이미지 시퀀스** 🎞 | 평소. 갇혀 있는 내내 돈다(숨쉬기·덜컹거림) |
| 창살(해제) | **스틸 한 장** | 잠금이 풀린 뒤. 자물쇠가 떨어지고 열린 창살 |

> ⚠️ **안쪽을 비워서 그릴 것.** 동물은 코드가 창살 **뒤에** 깔고, 이 그림을 그 위에 덮는다.
> 창살 사이가 불투명하면 갇힌 동물이 안 보인다. 동물을 그림 안에 그려 넣지 말 것 —
> 스테이지마다 갇힌 동물이 다르다.
>
> 두 장은 **같은 크기·같은 위치**여야 한다. 갈아끼울 때 자리가 틀어지면 덜컹거린다.
> 잠금 시퀀스는 **첫 프레임과 마지막 프레임이 이어져야** 한다 — 계속 반복 재생된다.

**동물** — 구출 대상. **이미지 시퀀스** 🎞 로 올린다(갇혀 있는 동안 계속 돈다).
토끼 · 원숭이 · 사슴 · 양 · 얼룩말 · 코끼리 (**6종. 이 6종이 전부다** — 도감과 창살이 같은 목록을 쓴다)

> 로비 시안에 있는 **펭귄은 구조 동물이 아니다.** 배경 그림의 일부로만 남고
> 슬롯을 두지 않는다. 붉은말도 발사대라 구조 대상이 아니다. 근거는 GDD §7 참조.

도감은 **첫 프레임**을 정지 그림으로 쓰므로, 첫 장이 대표 포즈가 되게 그린다.

## 7. 배경

| 슬롯 | 내용 |
|---|---|
| 게임 판 (중앙 9:16) | 헛간 바닥. 발사체는 이 컬럼의 좌우 끝에서 튕긴다 |
| 좌 패널 (175:288) | 헛간 내부 장식 — 동물·건초·타일 상자. 게임 요소 없음 |
| 우 패널 (175:288) | 헛간 내부 장식 — 동물·통·창밖 풍경. 게임 요소 없음 |
| 로비(목장) | 낮의 목장. 구출한 동물이 늘어나는 공간 |
| 타이틀 | 로고 + 붉은말 |
| 로딩 | 진행률 게이지가 얹힌다 |

**중앙 컬럼 전체가 판이다.** 나무 프레임은 좌우 패널로 옮겨갔으므로, 발사체가 튕기는
벽은 중앙 컬럼의 좌우 끝이다. 코드는 중앙 컬럼 안쪽 여백을 각 **10px**로 잡고 있다
(`src/ui/hex/geom.ts`의 `FIELD_INSET`, 논리폭 450 기준). 시안과 다르면 그 숫자 하나만
고치면 타일 크기가 자동으로 따라온다 — **아트를 다시 그릴 필요는 없다.**

### 파일을 놓을 위치

아래 경로에 파일만 드롭하면 게임 화면 배경에 자동 반영된다(위 §0 참고):

```
public/assets/hex/bg-board.png         중앙 게임판  (9:16)
public/assets/hex/bg-panel-left.png    좌 패널      (175:288)
public/assets/hex/bg-panel-right.png   우 패널      (175:288)
```

세 파일 모두 미업로드 상태(placeholder)에서는 화면이 단색으로 보이며, 이는 정상이다.

## 9. 우선순위

아트가 없어도 개발은 진행된다(색 육각 플레이스홀더). **아래 순서대로 도착하면 가장 효율적이다.**

1. **육각 타일 6종** ← 이게 없으면 게임 화면이 성립하지 않는다
2. 창살(잠금/해제) + 동물 1종 — 한 종만 와도 그 스테이지는 아트로 돈다
3. 붉은말 발사 자세
4. 게임 판 배경 (나무 프레임)
5. 말굽 타일 · 부스터 아이콘 3종
6. 나머지 동물
7. 로비·타이틀 배경, 로비 붉은말

## 10. 로비 시안에 대한 메모 (2026-09-04 추가)

최종 로비 시안에는 **미션 · 상점 · 코인 · 젬 · WORLD · EVENTS**가 그려져 있으나,
합의된 구현 범위는 **코어 + 도감 + 연속 플레이 + 로비 연출 + 레벨**이다(`docs/GDD.md` §7).

**아트는 시안 그대로 만들어도 된다.** 미구현 버튼은 코드에서 숨기거나 비활성으로
처리하며, 시간이 남으면 그때 살린다. 아트를 덜어낼 이유는 없다.

**작동할 것:** `PLAY` · `WORLD`(지도) · `ANIMALS`(도감) · 목장의 구출 동물 · 말굽 재화 · 설정
**보이되 작동하지 않을 것:** `MISSIONS` · `SHOP` · `EVENTS` · 코인 · 젬

> 2026-09-05: 하단 내비가 **HOME · WORLD · ANIMALS · EVENTS**로 바뀌었다.
> `SOON`은 없앴고 그 자리에 `WORLD`가 들어왔다.

## 11. UI · 로비 · 설정창 (2026-09-05 추가)

**`/ui.html` 에디터 한 곳에서 배치와 업로드를 다 한다.**
탭은 **로비 · 인게임 · 설정창 · 게임 에셋** 네 개다. 좌표계는 중앙 콘텐츠 컬럼 **450 × 800**.

| 하는 일 | 방법 |
|---|---|
| **배치** | 사각형을 끌어 옮기고 모서리 손잡이로 크기 조정. x/y/w/h를 숫자로 넣어도 된다. **저장**을 눌러야 반영된다 |
| **업로드** | 슬롯을 고르면 아래에 미리보기와 **업로드** 버튼이 나온다. 파일을 고르면 **바로 올라가고 게임 탭이 자동 새로고침된다** |
| **시퀀스** 🎞 | 🎞 표시가 붙은 슬롯은 **여러 장을 한 번에** 고르면 시퀀스가 된다. **파일 이름 순**으로 재생하므로 `walk_001.png` `walk_002.png` 처럼 번호를 붙인다. 한 장만 올리면 스틸로 동작한다 |
| **게임 에셋 탭** | 타일 6색·말굽·창살 12장·동물·게임판 배경처럼 **자리가 코드에 고정된 것들**의 업로드 목록. 묶음마다 구분선으로 나뉜다 |
| **영상 탭** | 인트로(프롤로그)·엔딩. 세로 화면 전체를 덮는다 |
| **영상 변환** | **로비 배경**에 mp4·mov를 올리면 webm(VP9)으로 자동 변환된다(원본은 안 남고 경로도 바뀐다). **인트로·엔딩은 예외** — 재생 방식이 달라 mp4 그대로 둔다 |
| **로비 탭의 「로비 배경 영상」** | 구출 마릿수마다 한 편인 전체화면 mp4 6칸. 카드에서 바로 재생해 확인한다 |
| **오디오 탭** | BGM 2종·효과음 6종. 카드에서 바로 미리듣기 |
| **게임 화면에서 편집** | 에디터 상단의 「🎮 게임 화면에서 편집 열기」 또는 주소에 `?editor=1`. **실제로 도는 게임 위에서** 항목을 끌어 옮긴다. 자동 저장 |

### 게임 화면에서 편집 (`/?editor=1`)

`/ui.html`의 사각형은 좌표만 보여 준다. 실제 화면에서 맞추고 싶을 때는 게임 위에서 직접 옮긴다.

**초록 격자가 곧 편집 모드 표시다.** 10px 잔선 · 50px 굵은선 · 중앙선 · 화면 테두리.
흰 베일 대신 선을 쓴다 — 색을 조정하는 중에 화면을 덮으면 색 판단이 흐려진다.

| 조작 | |
|---|---|
| **드래그** | 항목을 끌어 옮긴다. **10px에 붙고, Alt를 누르면 1px** |
| **모드 전환** | 패널의 큰 버튼 또는 **`** 키. 편집 중에는 게임 입력이 잠겨 PLAY도 눌리지 않는다 — 다른 화면(스테이지·설정창)으로 가려면 조작 모드로 바꿔 이동한 뒤 돌아온다 |
| **선택** | 이름을 누르면 화면에 **빨간 테두리**. 겹치면 **작은 쪽**이 잡힌다 |
| **⧉** | 슬롯 이름 복사 (터널 http 접속에서도 동작) |

| 항목별 조절 | |
|---|---|
| `x` `y` | 위치 |
| `w` `h` | 크기 |
| `배율` | 그림이 든 항목 — 0.05 단위 |
| `크기` + 색 팔레트 | 글자가 든 항목. **초기화**로 코드 기본값 복귀 |
| `숨기기` | 화면에서 끈다. 배경 아트가 이미 그린 폴백을 지울 때 |

**↩ 되돌리기 · ↪ 다시** — `⌘Z` / `⇧⌘Z`(윈도우는 `Ctrl`)로도 된다.
드래그 한 번, 값 하나 확정이 한 단계다. 타이핑 중에는 화면만 따라가고 값이 확정될 때
한 단계로 남으므로, 되돌리기가 글자 단위로 쪼개지지 않는다.
두 에디터가 각자 히스토리를 갖는다 — 업로드한 **파일**은 되돌리지 않는다(디스크에 이미 있다).

값이 바뀌면 자동 저장되고, **💾 지금 저장**으로 즉시 반영할 수도 있다.
아이콘은 무엇이 든 항목인지 알려 준다 — 🖼 그림 · 🅣 글자 · 🖼🅣 둘 다 · ◻︎ 빈 자리.

두 에디터는 **같은 파일**(`src/data/uiLayout.json`)을 고친다.

> **모든 아트는 원본 비율 그대로 들어간다.** 슬롯 크기는 「이 상자 안에 넣는다」는 뜻이지
> 「이 크기로 늘린다」가 아니다. 비율이 달라도 찌그러지지 않고, 남는 자리는 비워 둔다.
>
> 파일을 직접 `public/assets/` 아래에 드롭해도 된다 — 에디터는 같은 자리에 쓸 뿐이다.
> **png·jpg로 올리면 게임이 자동으로 webp로 바꾼다.** 무손실이고 투명 픽셀의 색까지
> 보존하므로(`-exact`) 가장자리 얼룩이 생기지 않는다. 용량이 크게 줄고 디코딩도 빨라진다.
> webp로 직접 올려도 된다.
>
> 허용: `png webp jpg jpeg gif mp4 webm mp3 wav` · 한 파일 최대 20MB.
> **업로드는 개발 서버에서만 동작한다** — 배포본에는 저장 기능이 없다.

> 올리지 않으면 된다.

#### 로비 배경 영상 — `scene-1.webm` … `scene-6.webm`

**구출한 마릿수마다 한 편.** 화면 전체를 덮는 루핑 영상이고, 배경·동물이 통째로
그려져 있다. 코드는 이 위에 숫자와 버튼만 얹는다.

| | |
|---|---|
| 비율·크기 | **9:16 · 1080×1920** |
| 형식 | **webm (VP9) · 무음** — mp4가 아니다. 아래 경고 참조 |
| 재생 | 무한 루프 — **첫 프레임과 끝 프레임이 이어져야** 끊긴 자리가 안 보인다 |
| 용량 | 에디터 업로드 상한 **80MB**(mp4 원본 기준). 그 안에서는 디자이너가 알아서 정한다 |

**누적이다.** `scene-3.webm`에는 세 마리가 다 있어야 한다. 한 마리씩만 든 영상 여섯 편이
아니라, 한 마리 → 두 마리 → … 여섯 마리로 늘어나는 여섯 편이다.

> ⚠️ **파일 번호는 마릿수지 동물이 아니다.** 에디터 칸 이름도 「로비 배경 · 3마리 구출」로
> 적혀 있다. 실제 구출 순서는 스테이지가 정하고(지금은 양 → 얼룩말·사슴) 동물 목록
> 순서와 다르므로, **몇 번째 동물인지 따지지 말고 「몇 마리가 보이는 장면인지」로 올린다.**

**한 편도 없어도 된다.** 그 경우 `bg.png` 스틸이 그대로 남는다. 중간이 비어도 된다 —
3마리인데 `scene-3`이 없으면 `scene-2`, 그것도 없으면 `scene-1`로 내려간다.

> 용량이 커도 첫 화면은 안 늦는다. 게임은 스틸을 먼저 깔고 영상이 준비되면 그 위에
> 얹는다. 그래서 상한을 넉넉히 뒀다 — mp4 원본을 80MB까지 받고, 서버가 webm으로
> 줄인 결과가 게임에 들어간다.

> **mp4로 올려도 된다 — 에디터가 알아서 webm으로 바꾼다.** png·jpg를 webp로
> 바꾸는 것과 같은 자리에서 처리한다(1080×1920 6초짜리 기준 2초 남짓).
> 인트로·엔딩은 이 변환을 거치지 않는다 — 아래 「인트로·엔딩은 왜 다른가」 참조.
> 손으로 `public/` 아래에 직접 넣을 때만 webm으로 만들어 두면 된다:
>
> ```
> ffmpeg -i scene-3.mp4 -c:v libvpx-vp9 -b:v 4M -pix_fmt yuv420p -an scene-3.webm
> ```
>
> ⚠️ **왜 mp4가 그대로면 안 되나.** h.264 mp4를 게임 화면 안에서 돌리면 영상이
> **첫 프레임에서 멎는다** — 파일은 정상이고 브라우저도 재생하는데(요소의 재생
> 시간이 흐른다) 그 프레임이 텍스처로 올라오지 않는다. 서버를 새로 띄우고
> mp4·webm을 번갈아 재서 확인했다: mp4는 12번 재는 동안 화면이 한 번도 안
> 바뀌었고, 같은 그림의 webm은 4초 주기로 돌았다.
>
> Safari는 webm 지원이 늦어 못 읽을 수 있다. 그 경우 영상 없이 `bg.png` 스틸이
> 그대로 남는다 — 화면은 깨지지 않는다.

**인트로·엔딩은 왜 다른가.** 그 둘은 게임 화면 **위에 DOM `<video>`로** 튼다
(`ui/videoScreen.ts`). 텍스처를 거치지 않으므로 mp4가 그대로 잘 돌고, webm 지원이
늦은 Safari에서는 오히려 mp4가 안전하다. 그래서 **인트로·엔딩만 변환에서 빼 두었다** —
`mp4`로 주면 `mp4`로 남는다. 텍스처로 올라가는 영상(로비 배경)만 webm이어야 한다.

**영상을 안 쓰려면** 그 칸에 파일을 올리지 않으면 된다 — 그 마릿수에서는 한 단계
아래 장면이, 그마저 없으면 `bg.png` 스틸이 나온다. 이미 올린 것을 끄려면
`src/data/uiLayout.json`에서 그 슬롯에 `"hidden": true`를 준다(전용 버튼은 없다).

### 확인창 — `public/assets/ui/` (2026-09-05 추가)

「홈으로」처럼 되돌릴 수 없는 행동 앞에 한 번 묻는 창이다. **설정창 위에 겹쳐 뜬다.**
자리는 `/ui.html` → **확인창** 탭에서 옮긴다. 패널 300×180이 기본이고, 그 안에
묻는 말 한 줄과 버튼 두 개가 들어간다.

| 파일 | 내용 |
|---|---|
| `confirm-panel.webp` | 창 바탕 한 장. **안내문구를 그려 넣어도 된다** — 넣었으면 `/ui.html`에서 「묻는 말」 슬롯의 **숨기기**를 켜야 코드가 그리는 글자와 겹치지 않는다 |
| `btn-confirm-cancel.webp` | **왼쪽** — 취소. 아무 일도 일어나지 않는 쪽이라 눈에 덜 띄게 |
| `btn-confirm-ok.webp` | **오른쪽** — 되돌릴 수 없는 쪽. 확실히 구분되는 색으로 |

> **버튼 글자는 아트에 넣어 준다.** 아트가 있는 버튼은 코드가 그림만 그리고 글자는
> 얹지 않는다. 글자 없는 두 장을 주면 똑같이 생긴 판 두 개가 나란히 서서
> 어느 쪽이 「나가기」인지 알 수 없게 된다.
>
> **좌우를 바꾸지 않는다.** 취소가 왼쪽·확인이 오른쪽인 것은 설정창의
> 「계속하기 · 홈으로」와 읽는 방향을 맞추기 위해서다.
>
> 안내문구를 아트에 넣으면 그 창은 **그 문장 전용**이 된다. 다른 것을 묻는 자리가
> 생기면 문구 없는 패널로 바꾸고 숨기기를 도로 꺼야 한다.

## 13. 소리 — `public/assets/audio/`

| 슬롯 | 파일 | 언제 |
|---|---|---|
| 로비 BGM | `bgm-lobby.mp3` | 로비에 들어갈 때 (반복) |
| 인게임 BGM | `bgm-stage.mp3` | 스테이지에 들어갈 때 (반복) |
| 발사 | `sfx-shot.wav` | 타일을 쏠 때 |
| 터짐 | `sfx-pop.wav` | 같은 색 셋이 사라질 때 |
| 구출 | `sfx-rescue.wav` | 우리가 열릴 때 |
| 클리어 | `sfx-clear.wav` | 스테이지 성공 |
| 실패 | `sfx-fail.wav` | 발사 소진 |
| 버튼 | `sfx-tap.wav` | 버튼을 누를 때 |

- **BGM은 mp3, 효과음은 wav.** wav는 디코딩이 없어 누르는 순간 울린다
- BGM은 **이음매 없이 반복**되게 잘라 준다. 앞뒤 무음이 있으면 한 바퀴마다 끊긴다
- 코드가 BGM에 0.5, 효과음에 0.8을 곱한다. 원본은 **피크 기준으로 정규화**해 준다
- 효과음은 설정창의 **SOUND**, 배경음악은 **MUSIC** 토글을 따른다
- 첫 사용자 제스처 전에는 브라우저가 재생을 막는다 — 로비 첫 터치에서 음악이 시작된다
- 파일이 없는 슬롯은 그냥 소리가 나지 않는다 — 없어도 게임은 정상이다
- `/ui.html`의 **오디오** 탭에서 올린다. 카드에서 바로 들어 볼 수 있다
