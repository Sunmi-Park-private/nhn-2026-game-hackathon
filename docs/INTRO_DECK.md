## 참고 문서에서 가져온 원칙

- **페이지 제목은 주장문이다.** 「코어 루프」가 아니라 「플레이의 반복 구조가 재미를 만든다」. 소제목(영문 라벨) + 주장문 + 본문 3층.
- **섹션 A·B·C·D로 묶고 섹션 표지를 둔다.** 각 표지에 그 섹션의 한 줄 요약.
- **페이지마다 강조 박스 하나.** 심사위원이 그 페이지에서 가져갈 문장 한 줄.
- **텍스트보다 인게임 스크린샷.** 기능 설명 옆에 실제 화면을 붙인다.

- 분량 기준: 참고 문서는 23p. 우리는 **18~22p** 목표.

## 페이지별 구성항목

### 1. 표지

- 대회명 라벨: `NAN 2026 HACKATHON — SUBMISSION [번호]`
- 게임명: **Red Horse Rescue 2026** [한글 부제 확정 필요]
- 로그라인 2줄:
  > 2026 병오년, 붉은말이 동료를 모은다.
  > 우리에 갇힌 동물 여섯을 구한다.
- 장르 한 줄: 육각 격자 머지 슈터 · 물리 기반 발사
- 하단: `TEAM [팀명] · BUILD WEB(모바일 세로) · 2026`
- 비주얼: 붉은말 + 케이지 키 비주얼 [아트 확정 필요]

### 2. 한 줄 피치 (OVERVIEW)

- 피치 문장: 붉은말을 **당겨** 육각 타일을 쏘고, **같은 색 셋**을 터뜨려 창살을 걷어내고, 갇힌 동물을 **구출**한다.
- 스펙 표
  - GENRE: 헥사 그리드 머지 슈터 (버블 슈터 × 머지)
  - PLATFORM: 웹 브라우저 · 모바일 세로 화면(논리 해상도 450×800)
  - PLAYTIME: 약 [ ]분 (6판 완주 기준 · 판당 100초 설계)
- KEY SCENE: 로비 → 인게임 → 구출 연출 → 레이스 스크린샷 4장

### 3. 코어 루프 (OVERVIEW)

- 4단계 카드
  1. **조준·발사** — 붉은말을 당겨 힘과 각도를 잡는다. 벽에서 튕긴다
  2. **터뜨리기** — 같은 색 3개 이상이 붙으면 전부 사라진다
  3. **낙하** — 받침을 잃은 덩어리가 떨어지며 획득된다. 말굽도 여기서 나온다
  4. **구출** — 창살 둘레 5면이 비면 자물쇠가 열리고 동물이 튀어나온다
- 강조 박스: 「터뜨리는 게 목적이 아니다. **창살 둘레를 걷어내는 것**이 목적이다.」

### 4. 섹션 표지 A — HOW TO PLAY

- 한 줄: 목표·조작·종료 조건을 한 흐름으로 설명합니다.

### 5. 목표 (OBJECTIVE)

- 헤드라인: 한 판 = 케이지 [N]개. 천장이 바닥에 닿기 전에 목표 마릿수를 구한다.
- START / PROGRESS / GOAL 3열
  - 시작: 육각 판 위에 색 타일과 창살(7칸 멀티셀)이 놓여 있다
  - 변화: 창살 둘레 12칸 중 상단 2칸을 뺀 10칸이 비어 간다. 열린 면마다 상단 타일에 금이 간다(0→5)
  - 최종: 5면 개방 → 창살 소멸 → 동물 구출 → 카운터 증가
- 강조 박스: 「상단 면은 조건에서 뺐다. 아래에서 쏘는 한 **영원히 닿지 않는 자리**는 규칙이 아니라 버그다.」
- 스크린샷: 금이 3줄 간 창살

### 6. 코어 디자인 (CORE DESIGN)

- 헤드라인: 쓸모없는 탄이 없다 — 무엇을 쏠지가 아니라 **어디에 붙일지**가 실력
- 좌: 색 6종 표 (빨·노·초·파·보·황금, 가시광선 파장 순)
- 우: 발사체 추첨 규칙
  - 판에 **있는 색에서만** 뽑힌다
  - 흔한 색일수록 자주(대략 53/27/13/7%)
- 강조 박스: 「한때 「발사체는 항상 빨강」이었다. 황금 하나 깨는 데 243발이 들어 **구출이 불가능**했다. 실제 플레이에서 발견해 되돌렸다.」 (GDD §5-2 근거)

### 7. 조작 (CONTROLS)

- 헤드라인: 조작은 설명보다 먼저 이해되어야 한다
- 조작 표
  - DRAG ↓ — 붉은말 앞발을 당기면 힘이 모인다. 직각삼각형 게이지 + 점선 궤적
  - DRAG ←→ — 당긴 채 좌우로 움직이면 각도. 새총식(당긴 반대로 날아간다)
  - RELEASE — 놓으면 그 힘만큼 포물선. 헛발이면 한 발 소모
  - TAP — 부스터 3종 선택 · 레이스 한 걸음
- 강조 박스: 「사거리가 유한해지자 **「얼마나 세게」**가 처음으로 실력이 됐다.」
- 스크린샷: 당김 → 게이지 → 발사 3연속

### 8. 실패 조건 (END CONDITIONS)

- CLEAR: 목표 마릿수 구출
- GAME OVER: 위에서 주기적으로 한 줄 내려온다(`pushSeconds`, 초기 15초). 판이 바닥 눈금에 닿으면 진다. 판 세로 20행
- 강조 박스: 「샷 리밋만으로는 재미의 축이 하나였다. 천장이 내려오면 **정확도와 속도**가 동시에 요구된다.」 (GDD §5-8 근거)
- 타임라인: 스테이지 1 → 6 흐름 [스테이지 수 확정]

### 9. 부스터·말굽 (BOOSTERS)

- 3종 카드: 💣 폭탄(반경 1 제거) · 🌈 레인보우(모든 색 매칭) · 🐴 말굽(다음 색으로 교체)
- 말굽 타일: 색 판정에 안 끼는 중립 타일. 받침을 잃어야 떨어지며 획득 → 수집 축
- 획득 경로: 레이스 최고기록 갱신 시 부스터 1개
- 강조 박스: 「추첨에 기대지 않고 **원하는 색을 직접 고르는** 수단이 말굽이다.」

### 10. 시그니처 피처 (SIGNATURE FEATURES)

- 3열, 각 열에 MECHANISM / IN PLAY / REPLAY
  1. **당겨 쏘는 물리** — 속도·중력·반사가 엔진에 있다 / 뱅크 샷과 파워 조절 / 같은 판도 손맛이 다르다
  2. **창살을 걷어내는 구출** — 멀티셀 케이지가 앵커라 둘레는 저절로 안 떨어진다 / 금 5줄이 진행도 / 어느 면부터 열지가 전략
  3. **6종 동물 메타** — 구출 → 목장·도감·운동회 한 축 / 레이스 탭 조작 / 최고기록 갱신이 부스터
- 각 열에 스크린샷 1장

### 11. 섹션 표지 B — THEME

- 한 줄: 공통 주제어 「2026년」과 기능 키워드 「물리법칙」+「[선택 키워드]」를 규칙으로 옮겼다.

### 12. 주제 해석 (THEME)

- 키워드 표: 공통 주제어 2026년 / 추첨 물리법칙 / 선택 [분해 · 수집 · 예측 · 제한 중 확정 필요 — GDD §2-3]
- 「2026년」 → 병오년 붉은말. 마스코트가 아니라 **발사대 그 자체**
- 구조 동물 6종: 토끼·원숭이·사슴·양·얼룩말·코끼리
- 강조 박스: 「붉은말은 구조 대상이 아니다. 화면 아래에서 위를 올려다보며 던지는 자세가 곧 캐릭터다.」

### 13. 물리법칙 (PHYSICS)

- 정의의 예시 3개를 **전부** 썼다는 표
  - 속도 → 발사 속도·포물선·사거리
  - 중력 → 부유 클러스터 낙하 · 발사체 낙하
  - 빛과 색 → 타일 순서가 가시광선 파장 순(700→400nm)
  - (+) 반사 → 입사각 = 반사각 뱅크 샷
- 강조 박스: 「물리법칙은 *어떻게 움직이는가*, 선택 키워드는 *무엇이 일어나는가*를 맡는다.」

### 14. 메타 (META)

- 흐름도: 타이틀 → 로비(목장) ⇄ 스테이지 → 구출 연출 → 다음 판 / 로비 → 도감 · 레이스
- 레이스: 6마리 동시 경주(내 동물 1 + AI 5) · 버튼 누르면 룰렛으로 선수 지정 · 탭 1회 = 한 걸음 · 최고기록 갱신 시 부스터
- 구현하지 않은 것: 미션·상점·재화·일일 보상. 이유 한 줄
- 강조 박스: 「심사위원이 **실제로 만질 범위**에 집중했다.」

### 15. 섹션 표지 C — CRAFT

- 한 줄: 데이터 → 엔진 → 렌더 한 방향. 적은 인원으로 밀도를 만든 방식.

### 16. 스테이지 설계 (LEVEL DESIGN)

- 제약: 심사 시연 10분 · 6판 · 판당 100초
- 난이도 단위: 「버틴 푸시 수」(샷 리밋 시절엔 여유율). 손잡이: 창살 수·깊이·색·2연결 밀도
- 데드락 방지: 생성 단계에서 빨강 3개 붙을 자리 보장
- 6판 표: 판 / 창살 수 / 목표 / 푸시 주기 [봇 측정 뒤 채움 — `docs/LEVEL_BALANCE.md`]
- 강조 박스: 「"3판은 좀 어렵게"는 튜닝이 안 된다. 먼저 **재는 단위**를 정했다.」

### 17. 아키텍처 (ARCHITECTURE)

- 다이어그램: `data(JSON·상수) → engine(순수 TS) → ui(Pixi)`
- 엔진이 pixi를 import하는 곳 0건 → 테스트가 헤드리스로 돈다
- 테스트 개수 [제출 직전 `npm test`로 실측]
- STACK 칩: TypeScript · PixiJS v8 · Vite · Vitest
- 강조 박스: 「JSON 스키마가 틀려도 게임이 못 뜨는 일은 없다 — 필드별 검증, 어긋나면 기본값.」

### 18. 워크플로우 (WORKFLOW · EDITORS)

- 4단계: 디자이너 에셋 → 터널 URL → 브라우저 에디터(`/ui.html`, `/?editor=1`) → 웹 실시간 확인
- 에디터 스크린샷: 레이아웃 슬롯 · 에셋 업로드 · 시퀀스 프레임
- 강조 박스: 「에디터가 채우는 건 **data뿐**, 게임 로직은 건드리지 않는다.」
- 각주: 저장은 dev 서버에서만. 배포본에는 디스크 쓰기를 넣지 않았다(이유 한 줄)

### 19. AI 활용 (AI IN THE MAKING)

- 인게임 런타임 LLM은 **쓰지 않았다**. 이유: 순수 규칙 게임, 억지 접목은 감점, 오프라인·쿼터·지연 리스크
- 제작 과정 4축: 로직 코드 생성 · 이미지 에셋 · BGM · **노드 스펙 분해 → 에이전트 위임**
- 스펙·플랜 문서 수 [`ls docs/superpowers/specs plans | wc -l`]
- 강조 박스: 「작업을 노드 스펙으로 쪼개 굴린 기록이 곧 **에이전트 설계서**다.」
- 다른 두 제출물(에이전트 설계서·디렉팅 명세서)로 가는 링크
